# M03 实验协议最终检查（2026-08-05）

## 1. 审计结论

M03 最终状态为 **PASSED**。本次只审计已有正式运行和论文产物，不重新训练模型，也不改动已部署
旧 TCN。审计覆盖 21 个五随机种子组、共 105 次正式训练或拟合运行，其中 80 次为三分类运行，
25 次为电池异常专用二分类运行；另核验 M01、M02、电池安全复评、电池二分类汇总、无监督检索和
零样本插补 6 组派生分析。

所有正式运行均完成，数据哈希、类别集合、验证/测试规模和相同 seed 的 split manifest 一致。
三分类正式结果中的 120 组测试指标均从保存的混淆矩阵重新计算，保存值与复算值的最大绝对差为
`2.220446049250313e-16`。正式运行涉及的三个历史 commit 中，统一指标实现
`src/tcn_moment/metrics.py` 的字节哈希完全相同。

CNN 五随机种子 AMP 运行全部稳定：配置和完成指标均记录 AMP 开启，指标、训练历史和最佳权重
均无 NaN/Inf。历史训练代码在整个运行中固定精度路径，遇到非有限 loss 会直接报错，不支持自动
AMP→FP32 回退；因此没有自动协议变化。M03 决策为保留并明确报告现有 AMP 结果，**不需要 FP32
补跑**。

## 6. 论文表格与主张边界

最终稿采用以下统一规则：

- 分类指标统一以百分数报告；表头已经声明 `%` 时，单元格不重复 `%`。
- 五随机种子聚合统一保留两位小数并写成“均值 ± 样本标准差”；逐 seed 值同样保留两位小数。
- 模型名称统一使用“1D-CNN（逐序列 z-score）”“TCN（原始尺度/逐序列 z-score/逐序列
  min-max）”“MOMENT 线性探测/最后两层微调/冻结表征 + RBF-SVM/完全微调”。
- 正式配置明确记录：1D-CNN 使用 AMP，TCN 使用 FP32，MOMENT 使用 AMP 和已记录的非有限检测/
  FP32 安全重算机制。
- 计算成本结论只覆盖已经观测的训练或拟合时间、峰值 GPU 显存、参数量或训练规模，不外推为
  线上推理延迟、吞吐、能耗或端到端生产速度。若论文以后主张部署推理效率，需另做统一硬件、
  batch size 和测量流程的推理基准。
