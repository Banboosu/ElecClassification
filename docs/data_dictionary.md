# 数据字段与标签约定

## 字段

| 字段 | 当前用途 | 说明 |
|---|---|---|
| `charging_station_id` | 样本唯一 ID | 用于固定划分清单、预测追踪和实验产物关联。 |
| `InsertedColumn` | 分类标签 | 训练前转为字符串，再由 `LabelEncoder` 编码。 |
| `charging_powers_str` | 功率时间序列 | 逗号分隔的浮点数序列。 |

## 标签

项目旧代码使用以下业务约定：

| 标签 | 项目中的含义 | 是否进入当前三分类实验 |
|---|---|---|
| `0` | 正常 | 是 |
| `1` | 充电器故障 | 是 |
| `2` | 电池异常 | 是 |
| `5` | 无效或不完整记录 | 否 |

标签 `0`、`1`、`2` 的项目内部含义有两类代码证据。`legacy/ceshi.py` 明确写有
`0=正常、1=充电器故障、2=电池异常` 的映射，并在诊断输出中沿用这三个名称；
`legacy/改进TCN.py` 和 `legacy/改进TCN优化输出曲线.py` 则直接读取 `InsertedColumn`，经
`LabelEncoder` 编码后用于训练，没有在训练过程中重新定义类别。旧版 TCN 代码与模型已经
投入内部实际使用；当前数据为真实内部运行资源，0/1/2/5 是现行业务数据口径，不是依据曲线
形态事后推断的实验标签。因此，论文与实验记录直接沿用上述标签名称和业务定义。

标签 `5` 的“无效或不完整记录”定义来自当前项目配置和既有 README；其数据也呈现明显的短序列
特征：11,435 条标签 5 中绝大多数短于 18 个时间点。标签 5 按内部既定数据处理规则不进入
0/1/2 三分类训练与主评估，其数量、长度和起始电压统计用于记录排除协议的一致性。

## 数据来源与披露口径

- 数据来自真实内部运行资源，并已服务于旧版 TCN 模型的实际部署与使用；
- 原始记录受内部数据管理与保密要求约束，不在论文或公开仓库中披露；
- 对外仅报告完成匿名化与聚合处理后的标签定义、样本统计、实验配置和模型结果；
- 论文不展示可反向识别内部设备、站点或业务主体的信息。
